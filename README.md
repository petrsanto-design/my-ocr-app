# ocr_app — автономное OCR-приложение для Windows (v0.1)

Одно окно, один `.exe`: открыть изображение → распознать → отредактировать →
скопировать или сохранить в TXT. Движок: **ocr-rs** (PaddleOCR через MNN), модель
**PP-OCRv5 eslav** (русский, украинский, белорусский + латиница). Модели встроены в
`.exe` через `include_bytes!`, в рантайме ничего не скачивается.

## Честные ограничения

- **PDF не поддерживается.** Библиотека pdfium требует отдельную DLL, что ломает
  идею «один .exe». Поддерживаются PNG, JPG, TIFF, BMP.
- **Качество русского ниже, чем у ABBYY FineReader.** PaddleOCR mobile-модель
  неплохо читает скриншоты и аккуратные сканы, но хуже справляется со сложной
  вёрсткой, таблицами, рукописным текстом, мелким шрифтом и плохими фото.
  Предобработки (выравнивание, бинаризация, коррекция EXIF-поворота) в v0.1 нет.
- PNG с прозрачностью автоматически кладутся на белый фон.
- **Многоколоночный текст не разбирается:** фрагменты упорядочиваются по строкам,
  колонки перемешиваются.
- **Выпадающий список «Русский / English / Оба» в v0.1 не меняет модель:** все три
  режима используют одну модель eslav (она читает и кириллицу, и латиницу).
  Список оставлен как точка расширения для отдельных моделей (см. `model_for` в
  `src/worker.rs`).
- **Размер .exe большой** (модели внутри). Точная цифра зависит от того, какие
  `.mnn` вы положите (FP16 вдвое меньше FP32); ориентир — десятки МБ.
  Реальный размер обязательно измерьте сами.
- **Целевая ОС — Windows 10/11 x64.** См. раздел про UCRT ниже.
- Окно приложения требует работающей видеосистемы (eframe по умолчанию рисует
  через wgpu). На совсем «голых» виртуальных машинах без графики оно может не
  запуститься — проверьте на целевых машинах.

## Что нужно для сборки (один раз, нужен интернет)

1. Rust (rustup) и целевая платформа:
   `rustup target add x86_64-pc-windows-msvc`
2. Visual Studio Build Tools 2022 с компонентом «Разработка классических
   приложений на C++» (MSVC + Windows SDK).
3. Python и CMake **не нужны** для обычной сборки. CMake нужен только для плана Б
   (`build-mnn-from-source`, см. Cargo.toml). Python — только если придётся
   конвертировать модели (см. ниже), и только на машине разработчика.
4. Интернет нужен для загрузки crates. Возможно, он понадобится и `ocr-rs` при
   сборке (библиотека использует предсобранные CPU-версии MNN «когда они
   подходят»; откуда они берутся, я не проверял). **В рантайме интернет не нужен.**

## Модели

Нужны три файла в каталоге `models/` (имена фиксированы, их проверяет `build.rs`):

| Файл | Что это |
|---|---|
| `models/PP-OCRv5_mobile_det.mnn` | детектор текста (общий для всех языков) |
| `models/eslav_PP-OCRv5_mobile_rec_infer.mnn` | распознаватель eslav |
| `models/ppocr_keys_eslav.txt` | словарь символов eslav |

Если файлов нет или это заглушка/указатель Git LFS, `cargo build` остановится
с понятным сообщением.

### Вариант 1: готовые .mnn из репозитория ocr-rs

Репозиторий: <https://github.com/zibo-chen/ocr-rs> (ветка `next`). В README
`ocr-rs` для языковых моделей заявлены имена `{lang}_PP-OCRv5_mobile_rec_infer.mnn`
и `ppocr_keys_{lang}.txt`. **Лежат ли там готовые файлы eslav, я подтвердить не
смог** (страница каталога недоступна для автоматической проверки). Откройте
`models/` в репозитории и посмотрите. Пакет `ocr-rs` на crates.io моделей не
содержит (каталог `models/` исключён из публикации), поэтому брать их нужно из git.

Если в репозитории лежит `PP-OCRv5_mobile_det_fp16.mnn`, а не `PP-OCRv5_mobile_det.mnn`,
скопируйте его под именем `PP-OCRv5_mobile_det.mnn`.

### Вариант 2: конвертация Paddle → MNN (FP16)

Если готовых файлов нет:

1. Скачайте Paddle-модели:
   - распознаватель: Hugging Face `PaddlePaddle/eslav_PP-OCRv5_mobile_rec`;
   - детектор: Hugging Face `PaddlePaddle/PP-OCRv5_mobile_det`
     (имя репозитория детектора проверьте на Hugging Face; оно не сверялось).
2. Словарь: файл `ppocrv5_eslav_dict.txt` из репозитория PaddleOCR
   (`ppocr/utils/dict/ppocrv5_eslav_dict.txt`). Сохраните его **без изменений** как
   `models/ppocr_keys_eslav.txt`. По примеру `debug_rec.rs` из ocr-rs служебные
   токены (blank и padding) библиотека добавляет сама.
3. Склонируйте репозиторий ocr-rs и запустите его скрипт конвертации
   (по умолчанию FP16):
   ```
   python script/convert_paddle_to_mnn.py --ocr-dir <папка с Paddle-моделями> --install-dir ./models
   ```
   Ожидаемую структуру входной папки и имена выходных файлов скрипта я не
   проверял: смотрите `--help` и README ocr-rs. Затем переименуйте результаты в три
   имени из таблицы выше. `--no-fp16` нужен только если требуется полная точность.

## Сборка

```
cargo build --release --target x86_64-pc-windows-msvc
```

Готовый файл:

```
target\x86_64-pc-windows-msvc\release\ocr_app.exe
```

### Обязательная проверка после сборки: `dumpbin /dependents`

Откройте «Developer Command Prompt for VS 2022» и выполните:

```
dumpbin /dependents target\x86_64-pc-windows-msvc\release\ocr_app.exe
```

В списке **не должно быть**:

- `MNN.dll` — иначе приложение не автономно;
- `VCRUNTIME140*.dll`, `MSVCP140*.dll` — иначе нужен VC++ Redistributable.

Ожидаемо там будут системные библиотеки (`KERNEL32.dll`, `USER32.dll` и т. п.) и
`api-ms-win-crt-*.dll` (это динамический UCRT, см. ниже).

Если проверка не прошла или линковка падает с `LNK2038` (несовпадение
RuntimeLibrary): предсобранный MNN несовместим с hybrid CRT. Включите в
`Cargo.toml` строку с `features = ["build-mnn-from-source"]` (нужны CMake и MSVC),
пересоберите и повторите проверку. Feature `mnn-dynamic` **не включайте**.

### Проверка на «чистой» системе

Скопируйте `ocr_app.exe` на Windows 10/11 без Python, Tesseract, VC++ Redistributable
и без интернета; запустите двойным кликом. Откройте скриншот с русским текстом и
нажмите «Распознать». Если вместо слов получается мусор или пропуски, проверьте
формат словаря (`ppocr_keys_eslav.txt`: один символ на строку, без изменений
относительно словаря PaddleOCR).

## UCRT и Windows 7/8.1

Hybrid CRT (`.cargo/config.toml`) линкует VC-runtime статически, но Universal CRT
(`ucrtbase.dll`) — **динамически**. На Windows 10/11 UCRT входит в систему, поэтому
дополнительных установок не требуется. На Windows 7/8.1 её по умолчанию нет, и
приложение не запустится без обновления Universal CRT. Целевая ОС проекта —
Windows 10/11; Windows 7/8.1 не поддерживаются.

## Сохранение в TXT

Файл пишется в UTF-8 **с BOM**, чтобы Блокнот Windows корректно показывал
кириллицу. Если BOM мешает вашим инструментам, уберите его в `save_txt`
(`src/app.rs`).

## Структура проекта

```
Cargo.toml
build.rs              проверка наличия моделей
.cargo/config.toml    hybrid CRT
models/               три файла моделей (не входят в репозиторий)
src/main.rs           точка входа
src/app.rs            GUI (eframe/egui 0.37)
src/worker.rs         поток OCR + каналы (crossbeam-channel)
src/models.rs         модели, встроенные через include_bytes!
```
